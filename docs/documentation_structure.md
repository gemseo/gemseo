# How this documentation is organized { #documentation-structure }

There are four kinds of pages here.
Tutorials teach,
how-to guides solve,
explanations justify,
references list.
Telling them apart saves a lot of scrolling.

## Tutorial or how-to? { #documentation-structure-tutorial-or-howto }

Both are executable Python examples, hence the confusion.
A tutorial shows the concepts interacting with each other:
it picks a problem,
then walks through the disciplines,
the design space,
the scenario
and the post-processing.
A how-to takes one question ("how do I aggregate constraints?"),
answers it,
and stops there.

If you are new to MDO or GEMSEO, go for the tutorials.
Else, if you arrive with a precise question, dive into the how-to guides.

## Finding your way between the parts { #documentation-structure-navigation }

You rarely need this page twice.
Explanation pages carry callouts to the tutorials and how-to guides that use their concept
(see [Discipline](user_guide/concepts/discipline/discipline.md)),
and tutorials close on the how-to guides going further.

The [home page](index.md) cuts the same content per goal rather than per kind.
Pick "connect a model" or "optimize a design"
and you get the explanations,
tutorials,
how-to guides
and references of that goal alone,
in reading order.

This four-way split is [Diátaxis](https://diataxis.fr).
It sorts pages by what you are doing when you open them,
not by the part of the code they describe.
