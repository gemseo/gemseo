`HashableNdarray` no longer raises a `ValueError` when wrapping an array that is not C-contiguous (e.g. a strided slice, a transposed array or a Fortran-ordered array) or a zero-dimensional array; such an array is hashed as its flat C-contiguous equivalent, so it has the same hash as its C-contiguous copy. As a consequence, an array that is not C-contiguous can now be used as a key of a `Database`; the hash of an array whose data type is `int32` (resp. `uint32`) is now computed as for `int64` (resp. `uint64`) on all platforms, both for the keys of a `Database` and for the data of the caches, so that it no longer depends on the platform; previously, this normalization was applied to the data of the caches on Windows only, so an `int32` array was hashed differently on Windows and on Linux. The hashing of the data of the caches also supports zero-dimensional arrays.
