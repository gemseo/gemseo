- The `gemseo.space.design` module is now a package; the import
  `from gemseo.space.design import DesignSpace` is unchanged.
- The `DesignSpace.normalize` attribute, mapping a variable name to the mask of the components to
  be normalized, was renamed to `DesignSpace.name_to_normalization_mask`;
  `DesignSpace.normalize` is kept as a deprecated alias.
- The `DesignSpace.unnormalize_vect` and `DesignSpace.unnormalize_grad` methods were renamed to
  `DesignSpace.denormalize_vect` and `DesignSpace.denormalize_grad`; the former names are kept as
  deprecated aliases, including the `ParameterSpace.unnormalize_vect` override.
- `DesignSpace.dimension` and `DesignSpace.normalize` were writable instance attributes; they are
  now read-only properties and can no longer be assigned.
- `DesignSpace.name_to_normalization_mask` (and its deprecated `DesignSpace.normalize` alias) and
  `DesignSpace.name_to_indices` return a read-only mapping instead of a plain `dict`; item
  assignment such as `space.normalize["x"] = mask` now raises `TypeError`, and code relying on
  `isinstance(..., dict)` or on `dict`-specific methods (e.g. `.copy()`) on these mappings must be
  adapted.
- The concatenated design-vector argument is uniformly named `x_vect`; it was named `x_vec` in
  `DesignSpace.get_active_bounds`, `x_c` in `DesignSpace.project_into_bounds`, `vector` in
  `DesignSpace.transform_vect` and `DesignSpace.untransform_vect` (and their `ParameterSpace`
  overrides) and `x_array` in `DesignSpace.convert_array_to_dict`; calls passing these arguments by
  keyword must be updated.
- `DesignSpace.project_into_bounds` no longer preserves the dtype of its `x_vect` argument: an
  integer input is now promoted to float whenever the bounds are float (any infinite bound, or a mix
  of float and integer variables). The result is numerically more correct (float bounds are no
  longer truncated to fit an integer array) but callers relying on an integer return dtype must cast
  explicitly.
- `DesignSpace.set_current_value` accepts any `Mapping`, and not only a `dict`, mapping a variable
  name either to a value or to `None` to mark the variable as having no value; a mapping of another
  type previously raised `TypeError`.
- `DesignSpace` now uses the `GoogleDocstringInheritanceMeta` metaclass (previously plain `type`); a
  subclass combining `DesignSpace` with another metaclass (e.g. `ABC`) now raises a metaclass
  conflict at class creation.
- Any unknown variable name now raises `KeyError` with the message `No variable named '<name>'.`:
  `DesignSpace.get_size`, `get_type`, `set_lower_bound`, `set_upper_bound`, `filter`,
  `filter_dimensions`, `rename_variable` and `set_current_variable` raised `ValueError`, while
  `remove_variable`, `get_lower_bound` and `get_upper_bound` raised a `KeyError` holding the name
  only.
- The bound arrays are now read-only: `DesignSpace.get_lower_bound`, `DesignSpace.get_upper_bound`,
  `DesignSpace.get_lower_bounds` and `DesignSpace.get_upper_bounds` (both the array they return and
  the values of the dictionary they return when `as_dict=True`) all return arrays with
  `writeable=False`. In-place mutation such as `space.get_lower_bounds()[0] = 0.0` now raises
  `ValueError: assignment destination is read-only` where it silently succeeded before; callers
  needing a mutable array must copy it, e.g. `space.get_lower_bounds().copy()`. The getters return
  views, so the read-only flag cannot be re-enabled either:
  `space.get_lower_bounds().setflags(write=True)` raises
  `ValueError: cannot set WRITEABLE flag to True of this array`.
- `DesignSpace.normalize_vect`, `DesignSpace.denormalize_vect`, `DesignSpace.transform_vect`,
  `DesignSpace.untransform_vect` and their `ParameterSpace` counterparts now require the array
  passed as `out` to have the dtype and the shape of the result, since an array supplied by a caller
  can neither be converted nor resized. A mismatch raises
  `ValueError: Expected an out array of dtype float64; got int64.` or
  `ValueError: Expected an out array of shape (2,); got (3, 2).` where the array was previously
  filled with truncated, downcast or broadcast values, or where NumPy raised `UFuncTypeError` from
  within the scaling.
