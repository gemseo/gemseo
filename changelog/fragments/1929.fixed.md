`DesignSpace.rename_variable` no longer desynchronizes the order of the current value
from the order of the variables. `Value.rename` moved the renamed variable's entry to the
end of the current-value mapping, even when the rename did not collide with another
variable's name; code reading `DesignSpace.get_current_value(as_dict=True)` by position,
e.g. concatenating its values or zipping it against `variable_names`, then got the
components of the wrong variables. Renaming a variable onto its own name is also now a
true no-op.
