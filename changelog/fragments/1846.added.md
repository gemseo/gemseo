Imports of modules and classes renamed or moved since the last release keep working for one deprecation cycle: importing from the old location is redirected to the new one and emits a `DeprecationWarning` naming the replacement, e.g. `from gemseo.utils.string_tools import MultiLineString` still works and points at `gemseo.util.string`. The rename tables are computed at runtime by `gemseo._deprecation` from the `bump-version.yml` file shipped with the package. The redirection also covers the old name of an attribute renamed in a module or package that kept its own name, e.g. `Radar` in `gemseo.post.dataset.radviz` and `RadarChart_Settings` in `gemseo.post`, the old name of a renamed module-level function, e.g. `traverse_add_diff_io` renamed to `set_differentiated_ios`, wherever it could be imported from, and the names that a package no longer re-exports, e.g. `DatasetFactory` in `gemseo.datasets`, `BaseMLAlgo` in `gemseo.mlearning`, `BaseStatistics` in `gemseo.uncertainty` and `XDSM` in `gemseo.utils.xdsm`, which are redirected to the modules defining their successors.
